# Корректная маршрутизация карточек в Orbis

## Почему возникала ошибка

При обращении к `/locations/3` старый процесс приложения либо сборка без обработчика маршрута
могли передать запрос обработчику статических ресурсов, из-за чего возникал `NoResourceFoundException`.
Промежуточное исправление «добавить ещё один `@GetMapping`» без проверки реального обработчика
не устраняло архитектурную неопределённость и не гарантировало корректный 404 для удалённого объекта.

## Что сделано

- Убран общий `PageController`, маршруты разделены между `PeoplePageController`,
  `LocationPageController`, `HomePageController` и `UtilityPageController`.
- Сохранён действующий способ отображения: Thymeleaf отдаёт `app.html`, JS получает JSON из REST API.
  Полная переделка карточек на серверный рендеринг **не проводилась**.
- Перед ответом `200` на `/people/{id}` и `/locations/{id}` контроллеры проверяют запись
  через соответствующий сервис. Отсутствие записи приводит к HTML 404.
- `PageErrorAdvice` формирует оформленную страницу 404 и ссылку на соответствующий список.
  `ErrorHandler` применяется **только** к REST-контроллерам и продолжает отвечать JSON.
- Строковые идентификаторы экранов централизованы в `AppScreen`.
- Скрипт `scripts/verify-current-version.ps1` проверяет актуальные имена файлов.
- Тест `WebRouteContractTest` покрывает существующие/отсутствующие записи и маршруты.

## Контракт

| URL | При существовании | При отсутствии |
| --- | --- | --- |
| `GET /locations/{id}` | HTML `app`, mode=`location-detail`, HTTP 200 | HTML `error/404`, HTTP 404 |
| `GET /people/{id}` | HTML `app`, mode=`detail`, HTTP 200 | HTML `error/404`, HTTP 404 |
| `GET /api/locations/{id}` | JSON `LocationResponse` | JSON `{ "error": "..." }`, HTTP 404 |
| `GET /api/people/{id}` | JSON `PersonResponse` | JSON `{ "error": "..." }`, HTTP 404 |

## Обновление локальной версии

1. Остановить старое приложение в IntelliJ, проверить порт 8080.
2. Распаковать архив **в отдельную папку**, открыть именно её как Gradle-проект.
3. Запустить `gradle clean test bootJar`.
4. Запустить `gradle bootRun --args="--spring.profiles.active=local"`.
5. Войти и проверить переход по ссылке из карточки человека на локацию.
6. Проверить `/locations/999999999` — теперь должна быть страница 404 в стиле Orbis.

**Базу данных не очищать:** entity, миграции, URL REST API и PostgreSQL-схема не изменены.

## Проверки в среде создания архива

Синтаксис JavaScript проверяется через `node --check`, проверяется структура контроллеров,
маршрутов и архива. Наличие правильных исходников ещё не доказывает корректность старого
процесса, запущенного на компьютере пользователя. Полная Gradle-сборка должна пройти локально.
